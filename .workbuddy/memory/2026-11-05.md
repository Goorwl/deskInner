- 关键结论（供后续复用）：
  - 零服务器直连可行：`src/client.rs:440-467` 命中 IP/域名端口即 return，绕过 rendezvous；被控端 `src/rendezvous_mediator.rs:1344-1412` 的 `direct_server` 监听 TCP 21118。
  - 端口推导：RENDEZVOUS_PORT=21116；直连 21118（RENDEZVOUS_PORT+2 = RELAY_PORT+1）、LAN 发现 UDP 广播 21119（+3）、hbbs 21115/21116、hbbr 21117、API 21114。
  - **坑1**：LAN 发现只返回 ID 不返回 IP（`src/ui_interface.rs:859-870`），点发现列表仍走 ID → rendezvous 路径，无服务器时连不上；必须手输 IP。
  - **坑2**：`stop-service=Y` 会同时关掉 direct_server（`rendezvous_mediator.rs:1358-1361`），不能用来只关公网注册。
  - **坑3**：直连传 `secure=false`（`rendezvous_mediator.rs:1403`），`identity_handshake` 跳过签名 ID 与密钥交换（`src/server.rs:264-351`），`io_loop.rs:240-242` 特意豁免不安全警告 → 按明文传输对待，必须强密码 + IP 白名单（支持 CIDR）。
  - **坑4**：默认启动仍有公网出站：`src/main.rs:15` NAT 探测、`rendezvous_mediator.rs:319-344` 注册循环。解法：`custom-rendezvous-server` 填内网 IP（如 192.168.3.100），派生 API 为 `http://<IP>:21114`（`common.rs:1270-1292`），并附带关闭 UDP/IPv6/WebRTC punch（`common.rs:1341-1352`）。
  - 默认开关：`enable-lan-discovery` 默认开、`direct-server` 默认关（`flutter/lib/common.dart:1616-1630` option2bool 规则）。
  - `is_outgoing_only()` 会让 `start_all` 空转 → 被控端不监听（`rendezvous_mediator.rs:283-289`）。
  - 方案 B（完整）：内网自建 rustdesk-server（独立仓库，本 checkout 不含）→ secure=true 有加密、发现列表可用。
- 项目现状：非 git 仓库；`libs/hbb_common/` 子模块目录为空 → 当前副本无法直接 cargo build；纯 LAN 使用无需改代码，建议直接用官方二进制。

## 追加：不自建服务、纯 IP 发现+连接的可行性（用户第 3 轮追问）

- 用户明确约束：不自建、不要外网服务器、想用 IP 直接发现并连接。已更新 `LAN-ONLY-FEASIBILITY.md` 新增第 6 节（原风险节顺延为第 7 节），**本轮只做分析，未改任何源码**。
- 关键新发现：LAN 发现数据里**本来就有 IP** —— `src/lan.rs:274-283` 把 UDP 回包源地址 `addr.ip().to_string()` 存为 `DiscoveryPeer.ip_mac` 的 key（供 WoL 用，`src/lan.rs:86-104`），`src/lan.rs:329` 多网卡会累积。断点在 `src/ui_interface.rs:861-873` 的 `get_lan_peers()` 只吐 id/username/hostname/platform，把 IP 丢了；`peer_model.dart:33-52` 无 ip 字段；`peer_card.dart:71,77,1599` 连接传 `peer.id` → 走 rendezvous → 无服务器失败。
- 结论：IP 连接开箱可行；内置发现页一键连开箱不行，但约 3 处小改动即可（get_lan_peers 加 ip 字段 / Peer.fromJson 解析 / peer_card 连接改用 ip），仍零服务器。注意别动 peer.id（remove_discovered、send_wol 依赖）；Web bridge.dart:1129-1143 是 UnimplementedError。
- 零改动替代：外部扫 21118 或固定主机名 `pc1:21118`（client.rs:455 is_domain_port_str）；连过一次后 IP 原样作为 peer id 存入「最近连接」（`client.rs:956` id: peer.to_owned()、`:3053` PeerConfig::load(&self.id)），以后一键重连 → 内置静态设备列表。
- 待验证：`is_ip_str`/`is_domain_port_str` 实现在缺失的 hbb_common，带端口 IP / 主机名写法未实机验证；方案 2 改动未编译。

## 第 4 轮：用户确认「只在内网，不需要加密、白名单，全部移除」

- 约束定稿：不自建、不接外网、只走 IP 直连；加密与白名单从方案中全部移除。
- **核心代码核查结论（重要，供复用）**：这两项在 IP 直连路径上本来就没生效，无需改源码：
  - 加密：直连 accept 传 `secure=false`（`rendezvous_mediator.rs:1403`），`identity_handshake` 在 secure=false 时整个跳过密钥交换（`server.rs:264-351`）→ 无加密代码执行。

  - 因此"移除"= 从方案/文档去掉要求，源码 0 改动；硬删代码会破坏协议互通且 hbb_common 缺失无法编译验证。
